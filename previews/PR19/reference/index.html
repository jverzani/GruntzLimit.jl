    GruntzLimit.gruntz_limit

    source 
    gruntz_limit(f, x, x0 = Inf; dir = :+, build = nothing, lift = nothing, signs = ())

    Compute \(\lim_{x \to x_0} f(x)\) with Gruntz's algorithm.

    • f: a symbolic expression implementing TermInterface's iscall, operation and arguments (e.g. a SymEngine Basic or a Julia Expr).

    • x: the variable, the same object that appears in f (a Basic symbol, or a Symbol for an Expr).

    • x0: Inf, -Inf, or a finite point: a number or an expression not containing x.

    • dir: :+ (from the right, the default), :- (from the left) or :both (both one-sided limits must agree). Only used for finite x0.

    • build: build(op, args...) constructs a compound result term. When x is a Symbol (Expr input) the default is Expr(:call, nameof(op), args...), giving an unevaluated Expr; otherwise it calls op(args...), which is right for types like SymEngine's Basic.

    • lift: converts plain Julia numbers (and π) in the result to the symbolic number type. The default uses the constructor of typeof(f) when that is a non-Real Number (as with Basic); otherwise numbers are left as they are.

    • signs: signs of parameters, or of expressions in them, as pairs c => s with s one of :positive, :negative, :nonnegative, :nonpositive, :zero or :nonzero (e.g. Dict(a => :positive) or Dict(a - 2 => :negative)). c is written like f: a Symbol or Expr for an Expr, a term of the same package otherwise. Consequences are used (a > 2 from a - 2 > 0). A zero is solved for a parameter, which is substituted. Without them, a parameter is a real number of unknown sign. When the limit depends on a sign that is not decided, a GruntzError names the constant (see gruntz_cases). A constant that may or may not be zero is taken to be nonzero, so answers are generic (a/b for b != 0).

    Returns Inf, -Inf, an Int/Rational for rational limits, or otherwise a term assembled with build. Throws GruntzError when the limit does not exist or cannot be computed.

    Examples

    julia> using GruntzLimit

julia> gruntz_limit(:(sin(x)/x), :x, 0)
1

julia> gruntz_limit(:(1/x), :x, 0; dir = :-)
-Inf

julia> gruntz_limit(:((1 + a/x)^x), :x)
:(exp(a))

julia> gruntz_limit(:(atan(x)), :x)
:(1//2 * π)

    GruntzLimit.GruntzError

    source 
    GruntzError(msg)

    Thrown by gruntz_limit when a limit cannot be computed: the limit does not exist (bounded oscillation such as sin(x) at Inf, or one-sided limits that differ with dir = :both), the expression uses an unsupported function, or the algorithm as implemented cannot finish (e.g. the sign of a constant involving a free parameter cannot be decided).

    kind is :nolimit when the limit is known not to exist, :undefined when the expression is not defined (e.g. log of a negative number), and :fail otherwise.

    GruntzLimit.gruntz_cases

    source 
    gruntz_cases(f, x, x0 = Inf; dir = :+, build = nothing, lift = nothing, signs = ())

    The limit of f as in gruntz_limit, for each case of the free parameters in it. Where the limit depends on the sign of a constant with parameters, such as a - 2, or on whether it is zero, the limit is computed for each possibility (a < 2, a == 2, a > 2), a zero by solving for a parameter and substituting. Cases with the same limit are merged. Returns a LimitCases.

    signs is as for gruntz_limit, and restricts the cases. Parameters are not taken to be nonzero, so a == 0 is a case where it matters.

    julia> using GruntzLimit

julia> gruntz_cases(:(x^(a - 2)), :x)
LimitCases with 3 cases:
  a < 2  =>  0
  a == 2  =>  1
  a > 2  =>  Inf

julia> gruntz_cases(:(a^x), :x)
LimitCases with 4 cases:
  a <= 0  =>  undefined
  0 < a < 1  =>  0
  a == 1  =>  1
  a > 1  =>  Inf

    GruntzLimit.LimitCases

    source 
    LimitCases

    The result of gruntz_cases (a public type, not exported): a vector of conditions => limit pairs, the conditions a Vector of CaseConditions that all hold in the case (empty when the limit does not depend on the parameters). A limit is a value as returned by gruntz_limit, :nolimit when the limit does not exist, :undefined when the expression is not defined for those parameters, or a GruntzError when the case could not be computed.

    A LimitCases is an AbstractVector of the pairs (cs[2], cs[end], filter, ...). With values of the parameters, as pairs parameter => value or a Dict, calling it gives the limit for those values (the case's limit with the values substituted), indexing gives their case.

    cs = gruntz_cases(:(x^(a - 2)), :x)
cs[end]          # CaseCondition[a > 2] => Inf
cs(:a => 3)      # Inf

cs = gruntz_cases(:((a^x + b^x)^(1/x)), :x)
cs(:a => 2, :b => 3)                  # 3
cs[:a => 2, :b => 3]                  # the case: CaseCondition[...] => :b

    GruntzLimit.CaseCondition

    source 
    CaseCondition(lhs, rel, rhs)

    A condition lhs rel rhs on parameters, in a case of gruntz_cases. rel is one of :<, :<=, :(==), :!=, :>=, :>; lhs and rhs are terms of the input's type (made with build), or numbers.

    Internals#

    The module's docstring describes the design:

    GruntzLimit

    source 
    GruntzLimit

    Limits of univariate real expressions using Gruntz's algorithm (D. Gruntz, "On Computing Limits in a Symbolic Manipulation System", 1996).

    Expressions are symbolic terms implementing the TermInterface.jl methods iscall, operation and arguments, with operations that are Julia Functions. Tested targets are SimpleExpressions.jl, SymEngine.jl (Basic), SymbolicUtils.jl and Julia's Expr:

    using SimpleExpressions
@symbolic x
gruntz_limit(sin(x)/x, x, 0)          # 1
gruntz_limit(x^2 * exp(-x), x)        # 0
gruntz_limit(x^2 + 1, x, -Inf)        # Inf

import SymEngine; SymEngine.@vars y
gruntz_limit(atan(y)/y, y, 0)         # 1

gruntz_limit(f, x, x0 = Inf; dir = :+, build = (op, args...) -> op(args...), lift = auto, signs = ())

    • f is the expression, x the symbolic variable (the same object used in f).

    • x0 may be Inf, -Inf, or a finite number / term not containing x.

    • dir is :+, :- or :both (only relevant for finite x0).

    • gruntz_cases (same arguments) gives the limit for each case of the parameters.

    • Returns Inf, -Inf, an Int/Rational, or a term. Non-rational results are rebuilt by calling the operations as functions (+, *, ^, exp, log, sin, cos) on the pieces; with a symbolic variable inside that gives a symbolic term back. Constant results such as -π/2 or exp(1) stay symbolic too: for SimpleExpressions they are built as unevaluated terms (evaluate with r()), for SymEngine they use Basic constants, and for Expr input (x a Symbol) results are unevaluated Expr calls such as :(exp(1)). Pass build to construct results differently (e.g. maketerm-based). lift converts plain numbers/π into the package's number type; by default it is the constructor of typeof(f) when that is a non-Real Number such as Basic, so a SymEngine limit of exp(1) comes back as E, not a float.

    Operations understood (given as Functions; Symbol names are accepted too): + - * / ^ inv sqrt cbrt exp log abs sign floor ceil, sin cos tan sec csc cot, their inverses asin acos atan asec acsc acot, the hyperbolic sinh cosh tanh sech csch coth and their inverses asinh acosh atanh asech acsch acoth. Limits that do not exist because of bounded oscillation (e.g. sin(x) at Inf) raise GruntzError.

    Design: terms are converted to an internal canonical form (sums of monomials with rational coefficients/exponents over "atoms": variables, exp/log/sin/cos applications and multi-term bases). That supplies the zero recognition Gruntz's algorithm needs without depending on a particular CAS.
