    Usage#

    gruntz_limit(f, x, x0 = Inf; dir = :+, build = nothing, lift = nothing, signs = ())
gruntz_cases(f, x, x0 = Inf; dir = :+, build = nothing, lift = nothing, signs = ())

    computes \(\lim_{x \to x_0} f(x)\). The limit point x0 may be Inf, -Inf, a number, or an expression that does not contain x. For a finite x0, dir chooses the side the limit is taken from: :+ (from the right, the default), :- (from the left), or :both (both one-sided limits are computed and must agree).

    Rational limits come back as Int or Rational, and infinite limits as Inf or -Inf, whatever the input type. Other answers, such as \(e\) or \(\pi/2\), are rebuilt in the input's term type.

    SymEngine#

    With SymEngine, create the variable (and any parameters) with @vars. Then write the expression as you normally would.

    using GruntzLimit
using SymEngine
@vars x a

gruntz_limit(sin(x)/x, x, 0)
    1

    Limits at infinity are the default:

    gruntz_limit(x^2 * exp(-x), x)
    0
    gruntz_limit(sqrt(x^2 + x) - x, x)
    1//2

    Answers that are not rational are returned as exact Basic values:

    gruntz_limit((1 + 1/x)^x, x)
    \[e^{1}\] 
    gruntz_limit(atan(x), x, -Inf)
    \[\frac{-1}{2} \pi\] 
    gruntz_limit((sin(x)/x)^(1/x^2), x, 0)
    \[e^{\frac{-1}{6}}\]

    Parameters can appear in the expression and in the limit point:

    gruntz_limit((1 + a/x)^x, x)
    \[e^{a}\] 
    gruntz_limit((x^x - x^a)/(a^x - a^a), x, a)
    1

    One-sided limits:

    gruntz_limit(1/x, x, 0; dir = :-)
    -Inf
    gruntz_limit(sqrt(1 - cos(2x))/x, x, 0; dir = :-)
    \[ - \sqrt{2}\]

    Cancellation between exponentials, the kind of limit Gruntz's algorithm handles well:

    gruntz_limit(exp(x + exp(-x)) - exp(x), x)
    1
    gruntz_limit(1/x^2 - 1/sin(x)^2, x, 0)
    -1//3

    SymEngine's own infinity, oo, can be used as the limit point:

    gruntz_limit(x^x / exp(x), x, oo)
    Inf

    SymbolicUtils#

    With SymbolicUtils.jl, create the variable (and any parameters) with @syms, declaring them Real:

    using GruntzLimit
using SymbolicUtils
using SymbolicUtils: @syms
@syms x::Real a::Real

gruntz_limit(sin(x)/x, x, 0)
    1
    gruntz_limit((x^2 + 1) / (2x^2 - 3), x)
    1//2

    Answers that are not rational are built as SymbolicUtils terms with TermInterface's maketerm, so constants stay exact rather than becoming floating point numbers:

    gruntz_limit((1 + 1/x)^x, x)
    \[e^{1}\] 
    gruntz_limit(atan(1/x), x, 0; dir = :-)
    \[\frac{-1}{2} \pi\] 
    gruntz_limit(sqrt(1 - cos(2x))/x, x, 0; dir = :+)
    \[\sqrt{2}\]

    Parameters may appear in the expression and in the limit point:

    gruntz_limit((1 + a/x)^x, x)
    \[e^{a}\] 
    gruntz_limit(sqrt(x^2 + a*x) - x, x)
    \[\frac{1}{2} a\] 
    gruntz_limit((x^x - x^a)/(a^x - a^a), x, a)
    1

    A symbolic answer can be evaluated with SymbolicUtils' substitute:

    L = gruntz_limit((sin(x)/x)^(1/x^2), x, 0)
    \[\frac{1}{\left( e^{1} \right)^{\frac{1}{6}}}\] 
    SymbolicUtils.substitute(L, Dict(); fold = Val(true))
    \[0.8464817248906141\]

    Constants in SymbolicUtils input#

    SymbolicUtils turns some constants into floating point numbers when an expression is built. π*x keeps π exact, but atan(x) - π/2 becomes atan(x) - 1.5707963267948966. The limit is then taken for that floating point number, which changes the answer:

    gruntz_limit(x * (atan(x) - π/2), x)       # exact answer: -1
    Inf

    To keep π exact in such an expression, build it the way SymbolicUtils represents it in π*x:

    PI = SymbolicUtils.maketerm(typeof(x), identity, Any[π], nothing)
gruntz_limit(x * (atan(x) - PI/2), x)
    -1

    Julia Expr#

    TermInterface.jl defines iscall, operation and arguments for Julia's Expr, so a quoted expression works without any symbolic package. The variable is passed as a Symbol:

    using GruntzLimit

gruntz_limit(:(sin(x)/x), :x, 0)
    1
    gruntz_limit(:(1/x^2 - 1/sin(x)^2), :x, 0)
    -1//3
    gruntz_limit(:(x/abs(x)), :x, 0; dir = :-)
    -1
    gruntz_limit(:(floor(x)), :x, 2; dir = :-)
    1

    A parameter is just another Symbol, and it can also be the limit point:

    gruntz_limit(:((x^x - x^a)/(a^x - a^a)), :x, :a)
    1

    Expr answers#

    For Expr input, a non-rational answer is returned as an unevaluated Expr, so it stays exact and may contain parameters:

    gruntz_limit(:((1 + 1/x)^x), :x)
    \[e^{1}\] 
    gruntz_limit(:((1 + a/x)^x), :x)
    \[e^{a}\] 
    gruntz_limit(:(sqrt(x^2 + a*x) - x), :x)
    \[\frac{1}{2} a\] 
    L = gruntz_limit(:(atan(1/x)), :x, 0; dir = :-)
    \[\frac{-1}{2} \pi\]

    The result is an ordinary expression, so it can be evaluated:

    eval(L)
    -1.5707963267948966

    The answer is assembled by a build function, which receives an operation (a Julia Function such as +, *, ^, exp, log, sin, cos, atan, sqrt) and its arguments. For Expr input the default is (op, args...) -> Expr(:call, nameof(op), args...). Pass a different build to change this. For example, calling the operations evaluates constant answers to floating point:

    gruntz_limit(:((1 + 1/x)^x), :x; build = (op, args...) -> op(args...))
    2.718281828459045

    Supported functions#

    The operations understood are

    • arithmetic: +, -, *, /, ^, inv, sqrt, cbrt, abs, sign;

    • floor and ceil, when their argument has a finite limit;

    • exp, and log (one or two arguments);

    • trigonometric: sin, cos, tan, sec, csc, cot;

    • inverse trigonometric: asin, acos, atan, asec, acsc, acot;

    • hyperbolic: sinh, cosh, tanh, sech, csch, coth;

    • inverse hyperbolic: asinh, acosh, atanh, asech, acsch, acoth;

    • the error function erf and erfc, as in SpecialFunctions.jl.

    Inside the package, most of these are rewritten in terms of sin, cos, atan, erf, exp and log. An answer involving them is correct, but it may be written differently from the input. For example, \(\arcsin(1/2)\) comes back in terms of atan:

    L = gruntz_limit(:(asin(x)), :x, 1//2)
    \[\arctan\left( \frac{2}{3} \sqrt{\frac{3}{4}} \right)\] 
    eval(L) ≈ π/6
    true

    SymEngine simplifies the same answer when it is rebuilt:

    gruntz_limit(asin(x), x, 1//2)
    \[\frac{1}{6} \pi\]

    Each operation can be given as a Julia Function or as its Symbol name. The named constants pi/π, E/ℯ, EulerGamma, Catalan and GoldenRatio are recognised. In an Expr, the bare symbols pi, π and ℯ are treated as these constants, not as parameters:

    gruntz_limit(:(x * (atan(x) - pi/2)), :x)
    -1

    Anything else gives a GruntzError:

    try
    gruntz_limit(:(gamma(x)), :x)
catch err
    err
end
    GruntzError("unsupported function/operator `gamma` with 1 argument(s)", :fail)

    Parameters and cases#

    A parameter is taken to be a real number of unknown sign. gruntz_limit answers when the limit does not depend on the sign, as for

    gruntz_limit(:(x^a / exp(x)), :x)
    0

    which is 0 whatever a is. When the limit depends on the sign of a constant, a GruntzError names the constant:

    try
    gruntz_limit(:(x^(a - 2)), :x)
catch err
    err
end
    GruntzError("the limit depends on the sign of `a - 2`, which cannot be decided: give it with `signs`, or use `gruntz_cases`", :sign)

    A limit for each case#

    gruntz_cases computes the limit for each case of the parameters. When the limit depends on the sign of a constant such as a - 2, it is computed for a < 2, a == 2 and a > 2. The case a == 2 is computed by substituting a = 2. Cases with the same limit are merged:

    gruntz_cases(:(x^(a - 2)), :x)
    LimitCases with 3 cases:
  a < 2  =>  0
  a == 2  =>  1
  a > 2  =>  Inf
    gruntz_cases(:(x^a * log(x)), :x, 0)
    LimitCases with 2 cases:
  a <= 0  =>  -Inf
  a > 0  =>  0

    A limit can be :undefined for some parameters (a^x needs a > 0), or :nolimit (the one-sided limits differ):

    gruntz_cases(:(a^x), :x)
    LimitCases with 4 cases:
  a <= 0  =>  undefined
  0 < a < 1  =>  0
  a == 1  =>  1
  a > 1  =>  Inf
    gruntz_cases(:(1/(x - a)), :x, 0; dir = :both)
    LimitCases with 2 cases:
  a == 0  =>  nolimit
  a != 0  =>  -1 * a ^ -1

    gruntz_limit takes a constant that it cannot decide to be nonzero, and so gives the generic answer a/b here. gruntz_cases also gives the cases b == 0:

    gruntz_limit(:((a*x^2 + x)/(b*x^2 + 1)), :x)
    \[a b^{-1}\] 
    gruntz_cases(:((a*x^2 + x)/(b*x^2 + 1)), :x)
    LimitCases with 3 cases:
  b == 0 && a < 0  =>  -Inf
  b == 0 && a >= 0  =>  Inf
  b != 0  =>  a * b ^ -1

    The result is a GruntzLimit.LimitCases, a vector of conditions => limit pairs. Each condition is a GruntzLimit.CaseCondition, with terms of the input's type:

    cs = gruntz_cases(:(sqrt(x^2 + a*x) - b*x), :x)
[(string.(conds), v) for (conds, v) in cs]
    3-element Vector{Tuple{Vector{String}, Any}}:
 (["b < 1"], Inf)
 (["b == 1"], :(1//2 * a))
 (["b > 1"], -Inf)

    A LimitCases is a vector, so cs[1], cs[end] and filter work. Calling it with values of the parameters gives the limit for those values. The values are given as pairs parameter => value (or a Dict), with the parameters written as in signs below. Indexing with them gives the case, conditions => limit:

    cs = gruntz_cases(:((a^x + b^x)^(1/x)), :x)
cs(:a => 2, :b => 3), cs(:a => -1, :b => 2)
    (3, :undefined)
    cs[:a => 2, :b => 3]
    Pair{Vector{GruntzLimit.CaseCondition}, Any}(GruntzLimit.CaseCondition[a > 1, b > 1, a <= b], :b)

    A condition is shown solved for a parameter when it is linear in one. A case whose condition c == 0 cannot be solved for a parameter (a*b == 1, say) is not computed. The case's limit is then a GruntzError. Merging is pairwise, so a union of several cases may be listed in parts.

    Giving signs#

    TermInterface has no way to state assumptions, so signs are given with the signs keyword, to gruntz_limit or gruntz_cases. They are pairs c => s. Here c is a parameter or an expression in the parameters. s is one of :positive, :negative, :nonnegative, :nonpositive, :nonzero or :zero. For :zero, the equation c = 0 is solved for a parameter, which is substituted:

    gruntz_limit(:(x^a), :x; signs = Dict(:a => :positive))
    Inf
    gruntz_limit(:(x^(a - 2)), :x; signs = Dict(:(a - 2) => :negative))
    0
    gruntz_cases(:(x^a / (1 + x^b)), :x; signs = Dict(:b => :positive))
    LimitCases with 3 cases:
  a < b  =>  0
  a == b  =>  1
  a > b  =>  Inf
    gruntz_cases(:(x^a), :x; signs = Dict(:a => :nonnegative))
    LimitCases with 2 cases:
  a == 0  =>  1
  a > 0  =>  Inf

    Write the keys the way f is written: Symbols and Exprs for an Expr, and terms of the same package otherwise:

    @vars b
gruntz_limit(exp(a*b*x), x; signs = Dict(a => :positive, b => :negative))
    0
    gruntz_limit(x^(a - 2), x; signs = Dict(a - 2 => :negative))
    0

    Signs that follow from those given are used. Linear consequences (a > 2 from a - 2 > 0) are found by Fourier–Motzkin elimination. Products, quotients, powers and logarithms of parameters take their signs from their factors (log(a) has the sign of a - 1).

    Signs that leave a logarithm or a fractional power of the parameters without a valid argument (log(a*x) or sqrt(a) with a negative) make the limit undefined: a GruntzError of kind :undefined. Without such signs, gruntz_limit takes the parameters to be values for which f is defined, as it takes them to be nonzero.

    When there is no limit#

    A GruntzError is also thrown when the limit does not exist. For example, bounded oscillation:

    try
    gruntz_limit(sin(x), x)
catch err
    err
end
    GruntzError("argument of exp/sin/cos diverges (oscillation or essential singularity)", :fail)

    or one-sided limits that disagree, with dir = :both:

    try
    gruntz_limit(x/abs(x), x, 0; dir = :both)
catch err
    err
end
    GruntzError("one-sided limits differ", :nolimit)
